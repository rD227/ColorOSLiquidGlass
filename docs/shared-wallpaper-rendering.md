# 1.3.3：滑动时的模糊与共享壁纸

## 原因

旧路径是「每个文件夹裁一张背景 → 一次缩小到约 1/8 → CPU 模糊 → AGSL 折射」。
裁片原点随翻页移动，但一次双线性缩小只读取附近四个像素，没有平均整个缩小区域。
于是同一个壁纸点会被不同的采样网格处理，细线和色块出现跳变。放大时改成 LINEAR
只能消除可见的像素方格，不能补回缩小时漏掉的内容。

必须满足两个条件：缩小时前先过滤整个像素覆盖区域；静态背景不应因玻璃位置变化
而产生一张新的模糊纹理。

## 改动一：局部截取的抗锯齿

`BackdropBlur.blurCopy()` 用可分离的面积平均缩小，计算非整数边界的覆盖比例，
再执行原有 stack blur。源 bitmap 不被修改；零半径保留完整像素。
`BitmapShader` 显式启用 LINEAR，防止作为 RuntimeShader 输入时使用最近邻采样。

曾尝试连续三次双线性缩小，但 259×131 的细线测试仍出现 18 级灰度跳变，
所以最终实现采用面积过滤。最终固定壁纸点的灰度变化范围：

| 测试（移动 16 帧） | 原一次缩小 | 面积过滤 |
| --- | ---: | ---: |
| 8 像素周期条纹，256×128 | 255 | 0 |
| 单像素线，256×128 | 26 | 2 |
| 25 像素宽条纹，256×128 | 33 | 4 |
| 单像素线，259×131 | — | 2 |
| 25 像素宽条纹，259×131 | — | 5 |

这些是 0–255 的通道值，并不代表所有动画都完全没有残差。
一次手机测试中，512×384、radius=32 的处理耗时中位数为全尺寸 CPU 3.56 ms、
面积缩小后 CPU 1.12 ms。面积过滤比漏采样的直接缩小更贵，所以普通文件夹改走下面的共享路径。

## 改动二：普通文件夹共享 GPU 壁纸

```text
壁纸内容 / 窗口尺寸 / 模糊半径改变
    → 绘制一次根窗口大小的壁纸
    → GPU RenderEffect 模糊
    → 保存只读 HardwareBuffer bitmap

文件夹翻页 / 旋转 / 缩放 / 壁纸缩放
    → 更新本地坐标到壁纸坐标的矩阵
    → 从同一张纹理取样，再执行原有玻璃折射
```

- `GpuBackdropTexture` 负责一次 GPU 渲染和资源释放，输出保持在 GPU；没有像素读回。
- `SharedWallpaperBackdrop` 按根窗口共享一张纹理。缓存键包括壁纸 bitmap 身份及
  generation ID、根窗口尺寸和模糊半径，位置和翻页进度不进入缓存键。
- `BackdropCoordinates` 保留浮点和透视除法；Drawable 子区域偏移、父级变换和壁纸
  中心缩放都进入采样矩阵。翻页每帧更新坐标，没有隔一两秒刷新一次的节流。
- `BackdropCapture` 对普通文件夹只触发重绘，不再每帧隐藏 host、软件绘制整个桌面、
  生成小裁片。软件合成明确需要局部截图时才按需生成。
- 旧纹理不立即 recycle，因为已录制的显示列表可能仍在使用它；引用释放后由运行时回收。

GPU 部分使用 Android 公共 RenderEffect/HardwareRenderer 接口，没有移植闭源模块代码。
资源流程参考 [Android 官方示例](https://developer.android.com/guide/topics/renderscript/migrate)。

## 范围与验证边界

普通文件夹的背景现在明确取壁纸层。文件夹与其他图标在立体翻页时发生重叠，普通玻璃
不会再把整个 Launcher 层级里的其他图标烘焙进背景。拖拽、长按菜单以及显式窗口坐标
预览仍走需要的局部内容来源；通知与锁屏卡片继续使用已有来源和夜间颜色处理。
玻璃轮廓仍跟随 OEM 文件夹动画，采样背景固定在壁纸坐标中。

壁纸缩放通过矩阵复用模糊纹理，因此模糊宽度会随壁纸一起缩放。当前壁纸来源仍是
WallpaperManager 的 Drawable，不是动态壁纸 Surface 的实时录制。
首次生成或壁纸/半径改变会同步生成 GPU 纹理，不能把缓存命中性能等同于首次生成性能。

设备探针覆盖：真实 GPU 模糊、0 半径、120 次坐标更新复用、壁纸内容/半径/窗口尺寸
失效、旧帧生命周期、生产 AGSL 绘制、透视与子区域坐标、普通文件夹/菜单/拖拽路由。
这不替代 ColorOS 桌面上的翻页、解锁、拖拽与菜单视觉验收，也没有证明整机帧率达到
闭源模块水平。

## 1.3.4：玻璃中心的尖角

原来的 `rim = 1 - smoothstep(-rimWidth, 0, sd)` 把边缘光照范围写反了。
SDF 在内部为负，因此旧式让平坦内部的权重为 1、外边缘为 0。
圆角矩形内部存在「最近边发生切换」的对角线，法线方向在那里不连续；
把方向性光照应用到整个内部，就会画出三角明暗区域和中心尖角。

修正为 `smoothstep(-rimWidth, 0, sd)`，让内部权重为 0、边缘为 1。
平坦内部直接使用背景颜色，只有边缘光照或折射需要时才计算法线。
共享纹理的缓存、GPU 模糊与坐标映射继续使用 1.3.3 的路径。

电脑回归检查直接读取生产 shader 的 rim 表达式：旧代码三个用例均失败，
新代码通过。另补充了设备上的纯灰背景测试，检查内部无方向性接缝、边缘仍有高光。
