# 桌面长按菜单静止采样限频

## 问题与范围

原先桌面长按菜单的 Choreographer pump 在整个挂载期间逐帧请求绘制，
`onPreDraw()` 又无条件设置 dirty、清除 self-invalidate 抑制，并进入图标/壁纸合成。
菜单即使已经静止，也会重复捕获背景。

此次只调整 `colg_desktop_popup` 的采样调度；共享壁纸文件夹、音量条、通知及 SystemUI
悬浮菜单仍走各自原有路径。目标是减少静止期间的采样开销，不保证改善单次大菜单合成耗时。

## 行为

- 新增 `menu_backdrop_fps`，默认 1 Hz，支持 1/2/5/10/15/30/60/90/120，导入非法值回到 1。
  已保存的有效档位保持不变；如先前保存过 30，需手动将滑条调到 1 后保存。
- `PopupCaptureCadence` 组合现有 `CaptureCadence`，限制静止期间的捕获尝试。
- 初次捕获、明确刷新请求、几何变化、开启动画以及开启结束的最终一帧及时采样。
  关闭时的缩放、透明度、位置和尺寸变化通过几何检测及时采样。
- 周期性 pump 按下一个采样截止时间安排回调，避免静止时仍每个 VSync 主动请求遍历。
  普通 UI 绘制不受该设置限制，其他原因触发的 PreDraw 会在采样入口再次检查截止时间。
- 不补采错过的帧；销毁时清除节奏状态。重新挂载或显式标脏会请求新帧。
- 保留动态背景更新，未添加“静止后永远缓存”的路径。

UI 在“菜单采样背景”下提供有档位的桌面菜单静止采样滑条，使用已有 LiquidSlider。
本地/远程配置写入及回读校验均包括新字段。

## 验证

先 assembleRelease，再设置 JAVA_HOME、ANDROID_HOME，运行 `tests/Run-HostTests.ps1`。

- 模拟一秒 165 Hz PreDraw，九个档位分别接受 1/2/5/10/15/30/60/90/120 次静止采样。
- 在 1 Hz 下验证几何变化、开启动画、最终静止帧和显式刷新不受一秒间隔限制。
- 覆盖首帧、截止时间取整、几何变化、逐帧开启、最终静止帧、显式刷新、长停顿不追帧及 reset。
- 使用真实 GlassConfig 读写内存偏好接口，验证默认值、九档保存/读取、音量条独立值和非法导入值。

这些是确定性调度测试，不是设备显示帧率或端到端耗时测量。
2026-10-14 真机基线（改为 1 Hz 前）：静止窗口约每秒 23～26 次采样，
五个菜单实例的前期详细采样中位耗时约 39～55 ms，单次最高约 101 ms。
1 Hz 旨在减少静止期间的重复工作；展开时单次合成的开销仍需分别评估。
这些日志未测量修改为 1 Hz 后的效果。

## 真机诊断

启用 `log.tag.ColgPopupPerf=DEBUG` 后，原有前 12 次详细捕获耗时日志保留，
另输出每秒一次的 `cadence` 汇总：`captureAttempts`、`skipped`、`movingCaptures`。
静止时比较采样次数和 CPU 开销；开启/关闭动画的及时采样可能使窗口总次数高于设置值。
测试完成后恢复原日志属性。
