# 1.3.7：悬浮通知、菜单背景开关和滑条交互

## 滑条

拖动处理从覆盖整个轨道的透明层移到滑块上。按下时保留当前值，不再按点击轨道位置
跳转数值；实际拖动才发出修改。连续滑条与档位滑条共用此行为，保留原有滑块动画。
滑条修改单独提交。设备上拖动、RTL 和滚动面板交互仍需人工验收。

## 顶部横幅

用户确认指屏幕顶部的通知横幅。此前它与普通卡片一样使用共享壁纸，单纯限制重绘
频率不会降低首次全屏壁纸纹理生成的开销。现在解锁状态的横幅借用音量条的实时 App
采样链路，背景更新共用 volume_backdrop_fps（10/15/30/60/90/120，默认 30）。
两个控件各有自己的时间预算，彼此不会抢占采样次数；共享的是设置值和调度实现。

HeadsUpState 在系统通知行祖先上调用 isHeadsUpState，包含退出动画。
接口来源：[AOSP ExpandableNotificationRow](https://android.googlesource.com/platform/frameworks/base/+/bafc1f5a4e19842582a55ec1aae02e00d0b12f64/packages/SystemUI/src/com/android/systemui/statusbar/notification/row/ExpandableNotificationRow.java)。
如果 OEM 行接口不兼容，已有安装边界会报告通知适配失败并保留 OEM 绘制。

进入横幅时清除壁纸标记并绑定实时截图；回到普通通知时解绑并恢复共享壁纸。
锁屏横幅仍使用锁屏壁纸。通知的尺寸、圆角、裁剪、alpha 和夜间颜色规则沿用适配器。
截图排除 Surface 的策略复用现有音量路径，真实 OEM 横幅的排除效果尚待安装检查。

「顶部悬浮通知玻璃」关闭后横幅使用系统原样式，普通通知卡片保持现有玻璃。
该功能仍受「通知卡片与锁屏通知」总开关控制。配置保存后重启组件生效。

## 菜单

桌面菜单动画泵原先强制截一次，然后置 dirty，在随后 OnPreDraw 又截一次。
现在动画泵只请求重绘，截图统一在正常绘制前完成。这样减少重复的图标合成、裁图和模糊。

「菜单采样背景」关闭时菜单保留简单的半透明底色和轮廓高光，跳过来源采样与折射。
桌面菜单的截图、动画采样泵和强制截图入口都会跳过；SystemUI 菜单流也会停止。
音量、桌面文件夹和通知不受此开关影响。它仍受「修改菜单栏样式」开关控制。

打开时继续使用原有桌面图标或 App 内容来源，没有改成固定壁纸。
减少重复截图并不能证明开合卡顿的所有来源已消除，菜单实时图标合成依然有成本。
可关闭「菜单采样背景」比较实际开合效果。

## 验证

release 构建通过。设备探针验证 GPU 模糊、平坦中心、通知夜间颜色、缓存、横幅
状态与路由、绑定清理、菜单开关隔离及关闭时不分配 CPU 截图缓冲。
新增横幅测试使用模拟 OEM 通知行，不代表实际 ColorOS 横幅已经完成视觉/帧率验收。
配置读写、六档采样时钟和吸附规则的电脑测试也通过。
测试只把 APK 放到 /data/local/tmp 作为依赖，没有安装模块或重启系统组件。
