# 通知分组展开时的折射尺度

## 原因

SystemUI 在分组展开期间绘制整组背景；动画结束后隐藏整组背景，并通过
`getHeaderBgDrawable()` 设置独立标题背景。两者由不同的 `GlassDrawable` 绘制。
原先每个材质都用自己当前 bounds 的短边计算折射区域与偏移量，导致材质尺度随动画增大，
切换到较矮的标题背景时又突然缩小。光照方向没有改变这些折射参数。

修正前，同一组实测：

| 阶段 | 绘制高度 px | refractionHeight px | refractionAmount px |
| --- | ---: | ---: | ---: |
| 收起的整组背景 | 310 | 35.46461 | 183.4799 |
| 展开末期的整组背景 | 798 | 91.29278 | 472.3128 |
| 独立标题 | 154 | 17.617905 | 91.14808 |

## 修正

`NotificationRefractionScale` 从宿主向上找到分组父通知行，使用它的
`min(width, getCollapsedHeight())` 作为共同的材质参照。
整组背景、组内子通知和独立标题都在绘制时读取同一个参照，传入
`GlassDrawable.setRefractionReferenceSize()`。

`GlassDrawable` 只用这个参照替代两个折射参数公式中的短边值。
轮廓、裁剪、背景采样和展开动画继续使用各自的实际几何。
未分组通知、横幅、桌面等没有设置参照，继续使用原来的短边公式。
移出分组后参照恢复为 0，表示使用默认公式。

参照不依赖第一帧缓存：直接进入已经展开的组也能得到正确值。
真实内容、组宽度变化时会重新读取。没有使用 `mExpandAnimationRunning` 判断分组动画，
因为实测这种动画期间该字段仍然是 false。
移除了临时光照 Y 翻转实验。

## 验证

- release 构建、生产 AGSL/GPU 模糊与现有设备探针通过。
- 新增设备探针覆盖分组/标题/子通知共用参照、已展开时首次绘制、内容/宽度变化、移出分组。
- 在实际 SystemUI APK 上验证 `isSummaryWithChildren()` 与 `getCollapsedHeight()` 方法签名。
- 真机第一组背景高度 310–799 px、子通知高度 66–214 px、标题高度 154 px，
  三条绘制路径的 refractionHeight 始终为 35.46461，refractionAmount 始终为 183.4799。
- 第二组背景高度 230–654 px，组内材质参数同样保持一致。

以上确认了参数连续性，但用户复测发现标题出现时仍会多出明显的折射/色散。
原因是相同材质尺度并没有统一两块背景的局部轮廓、法线与色散坐标，
不能把参数连续性等同于视觉连续性。

## 标题的最终处理

独立分组标题通过 `setBottomRefractionEnabled(false)` 仅关闭下边缘光学位移。
上一轮整个标题关闭折射的实验已移除。
shader 根据像素到直边的距离，排除属于下边缘的区域，使该区域不执行折射与 RGB 分离采样。
标题下角为直角，因此这个判断与下边缘的几何一致；左右边缘和顶部仍然执行原有折射。
`refractionHeight` 继续参与原来的边缘高光宽度计算，模糊、透明度与亮暗高光保留。
普通通知卡片、组内子通知和横幅仍开启折射。
这个策略属于每块材质，不修改共享的 `GlassConfig`，也不冻结绘制或缓存旧帧。

设备 GPU 探针将下边缘像素与零位移输出对比，将其余像素与完整折射输出对比，
同时检查共享配置未变、恢复下边缘后默认输出恢复。

`HeaderEdgeProbe` 另外覆盖直接 BitmapShader 绘制路径和上圆下直的标题轮廓，
不通过桌面弹出菜单的 RenderEffect 路径。实测 1090×154 的标题在关闭下边缘时，
上半区变化像素数为 0，下半区变化像素数为 27966。
这确认了离屏绘制的边缘判定范围，不能替代系统动画、图层切换的完整视觉验证。
排查期间 Vector 曾记录旧 APK 路径不存在的错误；测试安装后仍需确认目标进程实际加载的代码。

## 临时诊断

`log.tag.ColgNotifTrace=DEBUG` 启用诊断，恢复为空后关闭。
仅记录对象标识、几何、透明度和折射参数，不读取通知正文。
稳定帧合并为心跳，几何变化逐帧记录；不要用启用日志时的流畅度做性能结论。
